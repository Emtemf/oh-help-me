# 存量代码规则

## 核心原则

- MUST: 新建文件严格遵循规范
- MUST: 修改已有文件时，只改用户要求的部分，不扩散
- MUST NOT: 不主动改用户没要求改的东西

## 判断方式：git diff

| git diff 状态 | 含义 | 行为 |
|-------------|------|-----|
| `A` (Added) | 新建文件 | 严格遵循规范 |
| `M` (Modified) | 修改已有文件 | 只改用户要求的，不扩散 |
| 不在 diff 里 | 存量文件未动 | 不加载相关规则，不影响上下文 |

**简单判断：git diff 里出现的 = 增量，git diff 里没出现的 = 存量**

## 具体行为

| 场景 | 行为 |
|-----|------|
| 新建文件（A） | 严格遵循 `clean-architecture/` 下其他规则文件的规范 |
| 修改已有文件（M） | 只改 diff 范围内的，不扩散到文件其他部分 |
| 存量文件未动 | 不主动修改，不提规范建议 |

## 禁止

- MUST NOT: 顺手改、顺便改、建议改用户没要求的代码
- MUST NOT: 在 code review 中对存量文件提规范建议（除非用户问）
- MUST NOT: 批量重命名、批量迁移、批量重构存量代码
